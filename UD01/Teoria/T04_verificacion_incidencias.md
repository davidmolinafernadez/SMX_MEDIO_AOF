# T04 · Verificar, diagnosticar y documentar

Una instalación termina cuando satisface la necesidad y supera una prueba. «No apareció error» no es una verificación.

## Prueba de aceptación

| Prueba | Resultado |
| --- | --- |
| Inicio | Abre sin errores y muestra la versión prevista |
| Edición | Crea y modifica un documento |
| Guardado | Cierra y recupera el contenido |
| Idioma | Corrige en castellano/valenciano |
| Exportación | Genera un PDF legible |
| Compatibilidad | Mantiene elementos esenciales |
| Recuperación | Autoguardado confirmado |

## Método de diagnóstico

1. Recoger síntoma literal, momento y condiciones.
2. Reproducir y acotar.
3. Formular una hipótesis comprobable.
4. Probar una sola modificación.
5. Repetir la situación que fallaba.
6. Documentar causa, acción y resultado.

El parte incluye ID, equipo, usuario, impacto, síntoma, pruebas, causa, solución, verificación y estado. Una captura sin explicación no demuestra el proceso.

La IA puede sugerir hipótesis si recibe contexto técnico, pero se eliminan datos personales y no se ejecutan instrucciones que no se comprendan. Los cambios delicados se contrastan con documentación oficial.

**Ejemplo:** palabras correctas subrayadas → comprobar idioma del texto → asignar castellano al estilo → escribir una frase nueva y verificar.
