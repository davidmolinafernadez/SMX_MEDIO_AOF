# 2. Formularios, informes y seguridad

El usuario no debería editar tablas directamente. Un formulario guía entradas; un informe comunica resultados.

## Formularios

Orden de lectura, etiquetas claras, listas para claves foráneas, campos obligatorios, valores predeterminados, mensajes comprensibles y botones limitados. Se prueba teclado, datos extremos, cancelación y duplicados.

## Informes

Título, periodo, filtros aplicados, agrupación, totales y paginación. Un informe operativo no muestra toda la base. Se exporta PDF y comprueba salto, encabezado y confidencialidad.

## Demostración Base/Access

El profesor usa el asistente como punto de partida y después corrige formulario de incidencias: cuadro combinado de cliente, estado limitado y descripción amplia. Crea informe mensual desde consulta, no desde tabla. Muestra una macro de apertura segura y su alternativa mediante formulario inicial.

## Seguridad y copia

Mínimo privilegio, contraseñas fuera del archivo, datos ficticios en clase, copia antes de importar y prueba de restauración. Cerrar la aplicación correctamente antes de copiar la base. Una copia no verificada es solo una esperanza.

## Práctica guiada

Construye formulario, introduce cinco casos, corrige uno, consulta y genera informe. Otro alumno ejecuta cinco tareas sin instrucciones orales. Registra tiempo, errores y mejora.

!!! success "Aceptación"
    El producto se considera listo cuando un usuario nuevo completa las tareas, la base conserva integridad y el informe contiene solo los datos necesarios.
