# NexoByte · Modelo de evidencia RA9 en empresa

El ejemplo utiliza datos inventados. En una empresa real se respetan sus herramientas y confidencialidad.

## Ticket anonimizado

| Campo | Ejemplo |
| --- | --- |
| Identificador | INC-2027-014 |
| Síntoma | Al exportar el informe, la segunda página aparece vacía |
| Impacto | No puede enviarse el cierre mensual |
| Diagnóstico | El área de impresión incluye columnas vacías con formato |
| Protección | Copia `Informe_antes_v01.ods` |
| Actuación | Revisar vista de salto, redefinir área y exportar copia |
| Verificación | PDF de dos páginas revisado por el usuario |
| Prevención | Incorporar comprobación a la guía de cierre |
| Escalado | No necesario; actuación dentro de permisos |

## Valoración de la tutoría de empresa

- Identifica el problema antes de modificar.
- Protege la información y respeta permisos.
- Consulta recursos adecuados y registra pruebas.
- Se comunica con claridad y no culpabiliza al usuario.
- Verifica el resultado, documenta y escala cuando procede.

Si la empresa no permite conservar capturas o tickets, valida estos desempeños en el registro de seguimiento. El profesorado evalúa RA9 combinando esa valoración con la entrevista de evidencias.
